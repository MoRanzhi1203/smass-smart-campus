# S23 容量基线与限流压测

> 状态：**TESTED**（4 个场景 + 限流验证全部 PASS，并修复 1 个真实性能缺陷）
> 脚本：`scripts/s23_capacity_benchmark.py`、`smass/settings_s23.py`、`smass/urls_s23.py`
> 证据：`.local/evidence/s23/s23_benchmark.json`

## 1. 目标

1. 给出**单进程基线**：登录页、登录提交、管理员首页、重模板报告页的吞吐与延迟分位；
2. 验证 **S15 限流**真实生效（容量保护不被绕过）；
3. 发现并修复容量相关的真实缺陷。

## 2. 方法

- 用 `django.test.Client` 在**当前进程内**驱动真实视图与 MySQL（库 `smass_s23_bench`，50 条学籍 + 1 个系统管理员）；
- 每线程独立 `Client`，结束 `close_old_connections()`，并发 4–6；
- 记录 P50/P95/P99、吞吐（rps）、`tracemalloc` 峰值内存、错误数；
- 库名硬校验 `smass_s23_` 前缀，结束自动删库。

> 注意：进程内压测**不含网络栈**，且受 GIL 限制，得到的是相对基线；
> 生产容量需用 locust/wrk 在同等规格机器上复测。

## 3. 实测结果（2026-10-30，Python 3.12.16 / MySQL 8.0.18 本机）

| 场景 | rps | P50 | P95 | P99 | 峰值内存 | 错误 |
|---|---|---|---|---|---|---|
| 匿名登录页 `GET /r21/login/`（并发 6） | 214.27 | 2.33 ms | 79.78 ms | 456.45 ms | 1.85 MB | 0 |
| 登录提交 `POST /r21/login/`（并发 4） | 37.24 | 25.52 ms | 709.28 ms | 852.64 ms | 0.88 MB | 0 |
| 管理员首页 `GET /r21/home/`（并发 4） | 49.77 | 30.30 ms | 47.57 ms | 50.21 ms | 1.08 MB | 0 |
| 可访问性报告 `GET /s19/`（并发 4，热缓存） | 7.69 | 55.17 ms | 3410.22 ms | 4176.00 ms | 1.66 MB | 0 |
| **限流验证** `/s15/api/v1/ping`（limit=10） | — | — | — | — | — | **第 11 次起 429** |

总耗时 21.49 s（含建库、迁移、灌数、压测、清理）。

## 4. 本轮发现的真实缺陷与修复

**`GET /s19/` 每次请求全量扫描 147 个模板**：首次压测 P50 **3772 ms**、吞吐仅 1.04 rps，
属于典型的"无缓存重计算"。

修复：`smass_a11y/services.py` 增加 `audit_dir_cached()`，用 Django 进程缓存（TTL 300 s）：

| 指标 | 修复前 | 修复后（热） |
|---|---|---|
| P50 | 3772.55 ms | **55.17 ms** |
| rps | 1.04 | **7.69** |

剩余问题：并发首次请求存在**缓存击穿**（P95 仍 3.4 s），因为 4 个线程同时未命中。
后续可用互斥预热或预热任务解决（已在边界中登记）。

## 5. 容量结论与建议

1. **读路径健康**：登录页 214 rps / P50 2.3 ms，管理员首页 50 rps / P50 30 ms；
2. **写路径受密码哈希约束**：登录提交 37 rps / P50 25 ms，PBKDF2 是主要开销；
   若需更高登录吞吐，可上调迭代次数与 CPU 的配比，或启用登录限流（推荐后者）；
3. **重页面必须缓存**：统计/审计类页面必须走缓存或异步生成，否则会拖垮 worker；
4. **限流有效**：`limit=10` 时第 11 次请求即 429，符合设计；
5. **部署建议**：
   - Gunicorn/uWSGI worker 数 = CPU 核数 × 2 + 1，DB 连接池 `CONN_MAX_AGE=60`；
   - 生产启用 Redis 作为 cache/session 后端，避免多 worker 各自缓存；
   - 对 `/s19/` 这类扫描型页面加"预热 + 定时刷新"，而不是让用户触发冷启动。

## 6. 已知边界

1. 进程内压测不含网络与反向代理，数值不能直接当生产容量；
2. 未做长稳压测（> 1 小时）与内存泄漏观察；
3. 未做数据库连接池打满、慢查询、锁等待场景；
4. 缓存击穿未修复（仅记录），需在 S24 前决定是否加互斥预热。
