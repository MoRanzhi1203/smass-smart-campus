# S21 安全事件响应 Runbook 与演练记录

> 状态：**TESTED**（控制点矩阵 10/10 + 负向演练 63 例全通过）
> 脚本：`scripts/s21_incident_drill.py`；证据：`.local/evidence/s21_incident_drill.json`
> 适用：SMASS 智慧校园综合管理平台（生产/预发/测试环境）

## 1. 目的与范围

本 runbook 规定安全事件的**分级、角色、检测、处置、取证、沟通与复盘**，
确保从"发现异常"到"恢复服务"有明确动作与责任人，且每一步可留证。

范围：账号与会话、特权 MFA、敏感操作审批、审计链、字段授权、数据披露、
API 令牌、文件上传、依赖补丁。

## 2. 事件分级与响应目标

| 级别 | 判定 | 首次响应 | 遏制目标 | 恢复目标 | 通报 |
|---|---|---|---|---|---|
| **P1 严重** | 数据泄露、特权账号被接管、审计链断裂、生产库被写 | ≤ 15 分钟 | ≤ 1 小时 | ≤ 4 小时 | 立即：安全负责人 + 校方主管 |
| **P2 高** | 越权访问成功、批量导出异常、API 令牌泄露、MFA 被绕过 | ≤ 30 分钟 | ≤ 2 小时 | ≤ 8 小时 | 1 小时内：安全负责人 |
| **P3 中** | 持续暴力破解、恶意上传被拦截、限流大规模触发 | ≤ 2 小时 | ≤ 8 小时 | ≤ 24 小时 | 当日：值班人 |
| **P4 低** | 单点扫描、依赖漏洞预警（无利用迹象） | ≤ 1 工作日 | 按计划 | 按计划 | 周报 |

**MTTD**（平均发现时间）目标 ≤ 15 分钟；**MTTR**（平均恢复时间）P1 ≤ 4 小时。

## 3. 角色

| 角色 | 职责 | 备份 |
|---|---|---|
| 事件指挥（IC） | 定级、决策、对外口径 | 安全负责人 |
| 技术处置 | 遏制、根除、恢复、取证 | 后端负责人 |
| 沟通 | 内部通报、用户告知、监管报送 | 办公室主任 |
| 合规与记录 | 时间线、证据保全、复盘归档 | 安全负责人 |

单人值守时，IC 与技术处置可由同一人兼任，但**对外沟通必须第二人复核**。

## 4. 检测信号与控制点映射

演练脚本按下列控制点逐条核对代码/配置落地情况：

| 控制点 | 名称 | 主要检测信号 |
|---|---|---|
| CTL-01 | 统一认证与会话安全 | 同账号多设备异常、空闲超时、设备强制下线 |
| CTL-02 | 特权角色强制 MFA | 特权账号未绑定/验证失败次数上升 |
| CTL-03 | 敏感操作双人审批 | 自批尝试、载荷摘要不匹配、审批超时 |
| CTL-04 | 审计与告警（哈希链） | 审计链校验失败、告警规则命中 |
| CTL-05 | 字段级策略授权 | 字段访问拒绝率突增、脱敏命中 |
| CTL-06 | 数据最小化与披露留痕 | 披露申请/导出异常、字段越界请求 |
| CTL-07 | API 令牌/scope/限流/防重放 | 401/403/409/429 突增、nonce 重放命中 |
| CTL-08 | 上传文件安全 | 类型/签名不匹配、超大文件、ZIP 炸弹 |
| CTL-09 | 跨模块负向测试集 | 回归失败即视为控制点退化 |
| CTL-10 | 依赖补丁基线 | pip-audit 新增漏洞、基线版本落后 |

## 5. 处置流程（五步）

1. **发现与定级**：按第 2 节定级，记录 `发现时间/来源/初判`；
2. **遏制**：优先切断影响面——吊销会话与令牌、停用账号、封禁来源 IP、
   暂停导出接口；**不要**先删日志或重启覆盖现场；
3. **根除**：定位入口（越权/凭据泄露/依赖漏洞），修复并补测试；
4. **恢复**：灰度恢复、观察 30 分钟、确认审计链连续；
5. **复盘**：24 小时内出复盘，7 天内完成改进项闭环。

## 6. 场景 Playbook

### 6.1 账号被盗 / 会话劫持（P1–P2）
1. 用 S17 设备管理**吊销该账号其他会话**；
2. 强制改密（`must_change_password`），必要时停用账号；
3. 查审计链定位时间窗内的写操作，评估数据影响；
4. 若为特权账号，按 6.2 处理。

### 6.2 特权账号 MFA 被绕过（P1）
1. 立即停用该账号并吊销全部会话与 API 令牌；
2. 检查 `MfaDevice` 状态与最近验证记录（`last_used_at`、失败计数）；
3. 重置 MFA 绑定（旧设备置 `disabled`），签发新恢复码；
4. 复核该账号近 7 天的双人审批工单与执行日志。

### 6.3 批量数据导出 / 泄露（P1）
1. 立即冻结披露通道（停用相关 `DataField`）；
2. 从 `DisclosureLog` 拉出导出记录（申请人/字段/行数/摘要）；
3. 核对审批链是否完整，判断是否存在自批或绕过；
4. 评估泄露范围，按校方要求启动通报。

### 6.4 API 令牌泄露（P2）
1. 吊销令牌（`revoke_token`），必要时停用整个客户端；
2. 按 `ApiRequestLog` 回溯异常路径与状态码分布；
3. 轮换 scope 最小化后的新令牌；
4. 检查幂等键是否被用于重放攻击。

### 6.5 恶意文件上传（P2–P3）
1. 隔离文件（私有存储），记录哈希；
2. 按 `smass_uploads` 的类型/签名校验结果判断绕过点；
3. 排查同批次上传与下载记录；
4. 修补校验规则并补负向测试。

### 6.6 审计链断裂（P1）
1. 立刻停止写入并保全现场（不要重启数据库）；
2. 用 `smass_audit` 校验接口定位断点序号；
3. 从数据库备份恢复断点后数据，比对哈希；
4. 复盘写入路径（是否有绕过服务的直接 UPDATE）。

## 7. 取证要求

- **只读保全**：取证期间禁止改写日志/表；需要导出时复制副本并计算 SHA-256；
- **时间线**：所有动作记录 ISO-8601 时间、操作人、命令、结果；
- **证据清单**：审计事件导出、应用日志、数据库 binlog 片段、浏览器/接口抓包、
  变更 diff（Git commit）；
- **保管**：证据目录 `.local/evidence/<event-id>/`，含 `manifest.json` 与 `SHA256SUMS.txt`。

当前状态：已遏制 / 处置中
