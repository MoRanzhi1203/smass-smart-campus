# 00 V2.0 升级路线图

> 基线：Git `34e6b1c`（旧库已物理删除）
> 产品配置：`smass.settings_product` · 开发库 `smass_product_dev`
> 架构不变：一套 Django 产品、一套认证与数据权威、学生/教师/管理三个工作台
> 文档目录：`docs/SMASS_V2_Product_Upgrade/`

---

## 1. 目标

在既有产品上完成四件事：

1. **业务闭环**：学生端能选课/签到/补签/销假/退费/入社等；教师端能完成教学、考勤、审批；管理端不再依赖旧 Bootstrap 专业工具。
2. **权限与安全一致**：复合身份不误限/不越权；真实接入 MFA/二次认证/审计。
3. **视觉统一**：Modern Campus SaaS 设计语言，三端一套 CSS，克制动效与配色。
4. **可验证**：每个任务都有代码、页面、测试、截图与回归证据。

---

## 2. 阶段与依赖

```
P0 基线核验（HEAD/DB/迁移/进程/文档）
 │
 ├─ A 安全与数据一致性（A01 范围 → A02 RBAC → A03 敏感操作 → A04 权威源）
 │
 ├─ B UI 设计系统（B01 方向 → B02 令牌 → B03 布局 → B04 字体/图标 → B05 组件 → B06 暗色）
 │
 ├─ C 学生端闭环（C01 选退课 … C07 学籍/寝室/个人中心）
 ├─ D 教师端（D01 教学 → D02 考勤 → D03 审批 → D04 辅导员）
 ├─ E 管理端产品化（E01 组织 … E08 统计运维）
 │
 └─ F 联动/性能/无障碍（F01 教学周 → F02 通知 → F03 列表 → F04 任务 → F05 性能 → F06 可访问性）
```

依赖关系：A 先于 C/D/E（权限不正确时业务闭环会把越权固化）；
B 与 C/D/E 并行，但每完成一个业务域就同步样式；F 在 C/D/E 基本完成后收口。

## 5. 风险与约束
