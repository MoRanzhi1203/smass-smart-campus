## 2. 未满足项的具体缺口

### 2.1 数据库级加密备份（条件 7）

| 项 | 现状 |
|---|---|
| Git 备份 | 2 bundle + 3 tar.gz + SHA-256 清单（`.local/git-backups/protected/`） |
| 数据库备份 | 未发现 `mysqldump` 产物；仅有演练库 `s22_backup.sql`（非正式库全量） |
| 加密 | 无 |
| 恢复验证 | 未对正式库做恢复演练（避免读全量 PII） |

**建议**：

1. 由数据所有者授权后，对正式库做 `mysqldump --single-transaction` 全量导出；
2. 立即用 `age`/`gpg` 加密，校验 SHA-256，存独立介质；
3. 在隔离库做恢复演练并比对指纹；
4. 记录备份密钥托管方式（不写入仓库）。

### 2.2 舍弃数据审批（条件 8）

| 项 | 行数 | 建议 |
|---|---|---|
| `app01_teacherposition` | 2 | 确认语义：职称？职务？再决定迁移/归档 |
| `app01_position` | 4 | 归档即可，无产品消费方 |
| 身份证号 | 5 | 不迁移；正式库保留（受 PII 管理） |
| QQ/地址/拼音 | 5 | 不迁移 |
| `django_admin_log`/`django_session` | 0 | 无需处理 |

**需要**：数据所有者对"不迁移清单"签字确认；本清单见
`01_Legacy_Table_Classification.md` §3。

### 2.3 正式授权（条件 9）

- 正式迁移、切换、停写旧库均需明确授权；
- 本轮只做隔离演练；正式库未变（迁移算法指纹 `940a687d…` 与
  `db_fingerprint` 指纹 `b914b39c…` 均与基线一致）。

## 6. 最终结论

> **旧库退役技术条件已基本具备（运行时零依赖、迁移与对账可复现、
> 回滚可演练），但治理条件未满足：缺少数据库级加密备份、
> 舍弃清单未审批、正式切换未授权。因此状态为
> `CONDITIONAL — NOT RETIREMENT_READY`。**
>
> 本方案不宣布旧库可物理删除；在完成 §2 三项缺口并取得书面授权前，
> 正式库继续只读保留，产品继续使用统一新库。
