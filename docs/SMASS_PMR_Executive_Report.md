## 3. 最重要的三个发现

### 3.1 旧密码兼容早已实现，但密钥已泄漏

`app01/services/accounts.py` 里：

```python
LEGACY_MD5_SECRET_KEY = '<REDACTED — 该字面量已移除，改为环境变量注入>'
```

原文记录：密钥曾**硬编码在源码**中（`django-insecure-` 前缀，长度不在文档中复述），
意味着旧 MD5 哈希（无盐、无迭代）**可被离线破解**。

> **2026-10-30 更新（S01 治理）**：该字面量已从源码移除。密钥改为仅能从
> 受限来源（环境变量 `SMASS_LEGACY_MD5_SECRET_KEY`）注入，且历史 MD5 兼容
> 校验默认**关闭**（需 `SMASS_LEGACY_MD5_COMPAT=1` 显式开启）。
> 详情见 `docs/SMASS_S01_Legacy_Secret_Containment.md`。

- 缓解：只在**校验**时用；命中即升级为 PBKDF2；不导出哈希
- 残余风险：升级窗口期内，若哈希泄漏仍可被解开
- 建议：**生产切换后强制全员改密或重置**
- 处置（历史）：当时不隐藏密钥（已在版本历史里），用断言固化事实
- 处置（现状，S01）：密钥从源码移除；断言改为“源码中不得出现该字面量”

### 3.2 CSV 导出在 10k 规模需 12.5 秒

| 规模 | p50 |
|---|---|
| 1k | 5 222 ms |
| 10k | 12 476 ms |

约 800 行/秒。生产数据量下不可接受。

**本轮只测不修**——PM6 的任务是测量。该数字作为 PM10 的 NO-GO 依据之一。

### 3.3 陈旧 legacy session 没有变成后门

迁移语境最危险的情形：`app01` 旧视图读 `session['info']`，
若迁移后仍信任"只有 info、没有 `_auth_user_id`"的会话，等于无凭证访问。

实测 4 个受保护端点全部拒绝。`/r10/` 是**公开页**（docstring 明示），
但实测不渲染 info 的姓名/id，且 `request.user` 为匿名。

## 5. 三个"反直觉"的实测观察

**观察 1：10k 的查询比 1k 更快**（15.70ms vs 26.64ms）

不是数据越多越快——1k 是首次跑（冷启动），10k 是第二次（已热）。
报告必须区分首查询与稳态延迟。

**观察 2：CSV 导出 1k→10k 只增长 2.4 倍**（非 10 倍）

说明内部有分批与缓存效应。但绝对值仍然过慢。

**观察 3：多进程 PID 数多于 worker 数**（4→7、8→11）

`ProcessPoolExecutor` 在两次 map 之间重建进程。这反而**更强地证明**是多进程——
如果是线程，`os.getpid()` 全都相同。
