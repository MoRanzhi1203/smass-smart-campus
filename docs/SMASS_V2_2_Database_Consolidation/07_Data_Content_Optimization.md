# 07 数据内容优化（去仿真化）

> 目标：普通业务页面不再出现“仿真 / Demo / Simulation”，但后台保留合成来源标记。

---

## 1. 名称优化（campus 实测）

| 对象 | 优化前 | 优化后 |
|---|---|---|
| 宿舍楼名称 | 仿真宿舍 1 号楼 | **1 号学生公寓** |
| 教学楼名称 | 仿真教学楼 1 | **第 1 教学楼** |
| 宿舍区 | 仿真东区宿舍 | **东区学生公寓** |
| 寝室名称 | 寝室 101 | **101 室** |
| 课程名称 | 计算机科学与技术（核心） | **专业导论 / 学科基础 / 专业核心 / 专业实验 / 专业选修 / 前沿讲座**；公共课 **高等数学 / 大学英语** |
| 活动名称 | 新生程序设计竞赛（1） | **新生程序设计竞赛** |
| 通知标题/正文 | 仿真通知 N / 这是仿真生成的… | **校园通知** / 这是系统生成的站内通知… |

验证（campus 库）：`Building/Room/Activity/Notification` 中含“仿真”的记录数均为 **0**。

## 2. 页面层调整

宿舍相关页面改用**名称**而非内部编码：

| 页面 | 调整 |
|---|---|
| 学生住宿页 | 楼栋显示名称 + 宿舍区；房间显示 `101 室`（原 `SIM-DORM-B01-101`） |
| 宿管工作台 | 楼栋名称 + 宿舍区（原显示 `SIM-DORM-B01` 编码） |
| 房间浏览 / 管理端寝室表 | 房间名称 |

## 3. 保留的后台来源标记

| 标记 | 位置 | 用途 |
|---|---|---|
| `StudentRecord.extra['sim_batch']` | 学籍扩展字段 | 追溯批次 |
| `SimulationBatch` / `SimulationObject` | `smass_simulation` app（campus 内） | 批次与对象索引、清理依据 |
| 内部编码前缀 `SIM-` | 组织/楼栋/房间/课程 code | 后台识别（页面不再显示） |
| 合成手机号 `100********` | 账号扩展 | 无效号段，避免真实联系 |
| `Payment.method = synthetic_bank` | 财务 | 明确为演练资金 |

## 4. 内容自然度检查

- 学院（10）、专业（35）、班级（560）均为真实命名规则，层级正确（学院→专业→年级/班级）；
- 每名学生有独立学号、姓名、班级、课程（8 门）、考勤与请假记录，不是同一套模板；
- 课程按专业 6 门 + 2 门公共课，教学班按班级×8 生成，排课 0 冲突；
- 宿舍 32 栋 / 15360 床 / 14280 在住，床位唯一、无超容量；
- 社团 20 个（4 类）、活动 40 场（报名含候补与签到）、账单 16800 张（60% 已缴）。

## 5. 限制

- 楼栋内部编码仍为 `SIM-DORM-*`（页面不显示），未做全库编码重写以降低破坏业务过滤的风险；
- 通知正文为统一模板句，未做逐条差异化。
