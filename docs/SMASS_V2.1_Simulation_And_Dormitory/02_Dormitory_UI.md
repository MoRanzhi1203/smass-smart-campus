# 02 宿舍 UI 与业务入口

> 三个入口共用 V2.0 `app.css` 与三端壳；数据来自 `smass_dormitory`。
> 产品配置已注册 `smass_dormitory`（产品库 +9 表，迁移已回滚验证）。

---

## 1. 入口与权限

| 入口 | URL | 可见范围 | 权限 |
|---|---|---|---|
| 学生住宿 | `/student/dormitory/` | 本人住宿、室友、申请 | 学生本人 |
| 宿管工作台 | `/dormitory/` | 授权楼栋 | 有 `DormManagerScope` 或 `system_admin`；无范围 → 403 |
| 房间浏览 | `/dormitory/rooms/` | 授权楼栋的房间与入住 | 同上 |
| 管理端宿舍 | `/admin/dormitory/` | 全部楼栋、审批、授权 | `admin_only`（学院管理员/系统管理员） |

宿管账号统一 `college_admin` 角色（可登录），实际范围由楼栋范围约束；**不授予 system_admin**，
也不因宿管岗位自动获得学籍/课程/财务写权限。

## 2. 学生住宿页

- **已分配**：楼栋 / 楼层 / 房间号 / 床位号 / 入住时间 + 室友表（姓名/学号/床位/学院）；
- **未分配**：明确显示“尚未分配床位”，不写“可能为走读”；
- **走读**：读取 `StudentRecord.extra.dormitory.mode == commute`，显示“走读生”；
- **申请**：报修（问题描述）、调宿（目标床位下拉 + 理由）、退宿（原因）；
- **历史**：调宿/退宿/报修最近 10 条及状态。

## 3. 宿管工作台

统计卡：负责楼栋、床位/入住、空床、今日入/退、待办数。
楼栋表：每栋寝室数、床位数、入住数、入住率。
待办：待审批调宿（批准 / 驳回含理由）、待处理报修（推进状态机）、待复查巡查（推进）。

## 4. 管理端

总览统计（楼栋/寝室/床位/入住/空床/住宿学生/占用率）、楼栋资源（宿舍区、适配、状态）、
待审批调宿/退宿、宿管授权表、待处理报修与巡查。

## 5. 业务规则与越权

- 调宿/退宿/报修正推都在服务层校验：目标床位空闲、房间/楼栋可用、学生当前有在住关系；
- 审批动作额外校验**目标楼栋在操作人范围**，越权返回 403；
- 学生只能查看本人住宿；室友信息仅显示姓名/学号/床位/学院。

## 7. 已知限制

- 宿舍资源的新建/编辑尚未提供产品表单（当前由仿真或管理端脚本生成）；
- 批量分配（按班级一键分床）未做；
- 住宿导入/导出未接入（可复用 E07 导出服务）；
- 宿管工作台的“房间名册”仅到房间级，未做床位级点名。
