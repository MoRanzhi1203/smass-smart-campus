---

## 1. 安全清理（P9）

```powershell
# 计划（不删除）
python manage.py seed_campus --cleanup --settings=smass.settings_simulation

# 执行删除
python manage.py seed_campus --cleanup --confirm --settings=smass.settings_simulation
```

只处理仿真数据前缀：`SIM-*` 组织/资源、`sim_*` 账号、`SEC-`/`COH-` 教学、`S…` 仿真学号、
`SIM-BILL-*`/`SIM-PAY-*` 财务、`sim:` 通知、`SIM-CLUB-*` 社团、`simulation` 活动。

| 实测（medium dry-run） | 计划 |
|---|---|
| 选课 / 考勤记录 / 考勤场 | 51840 / 12960 / 432 |
| 住宿分配 / 床位 | 5508 / 6240 |
| 账单 | 6480 |
| 教学班 | 1728 |
| 学生 / 账号 / 组织单元 | 6480 / 6945 / 264 |

执行后核对：学生 0、账号 0、组织单元 0、床位 0；`--verify` 无法再运行（数据已清空）。

## 3. 页面性能采样（P8）

方法：Django test client + `CaptureQueriesContext`（单请求、串行、无并发），
隔离库 medium（6480 学生 / 1728 教学班 / 51840 选课 / 5508 住宿）。

| 页面 | 状态 | SQL 数 | 耗时 |
|---|---|---|---|
| 学籍列表（6480） | 200 | 27 | 83 ms |
| 账号列表 | 200 | 26 | 28 ms |
| 宿舍管理 | 200 | 41 | 66 ms |
| 排课管理 | 200 | 29 | 56 ms |
| 教学班名单 | 200 | **29** | **59 ms** |
| 班级考勤统计 | 200 | 38 | 90 ms |
| 教师课表 | 200 | 35 | 45 ms |
| 学生课表 | 200 | 33 | 39 ms |
| 学生住宿 | 200 | 45 | 67 ms |
| 活动列表 | 200 | 29 | 53 ms |
| 宿管工作台 | 200 | 44 | 63 ms |
| 房间浏览 | 200 | 34 | 67 ms |

**优化**：教学班名单存在 N+1（模板逐行访问 `account.student_profile`），
`select_related` 补充后 **149 → 29 查询、127 → 59 ms**。

**结论**：所有采样页面列表均分页或限定条数，未出现“一次加载 6480 行”的页面；
查询数与耗时在单请求下可接受。

## 4. 说明与限制

- 单请求采样**不等于**并发压测；未做 p95/p99 与并发指标；
- large（16800）未生成实测（时间与磁盘成本），容量公式与分页策略一致；
- 学生住宿页 45 查询中主要是历史与申请列表，可后续按需分页。
