## 2. 判定理由

**NO-GO** 的直接原因（任一未满足即 GO 不成立）：

1. **门禁 5 的审计回滚追溯缺失**：`--rollback` 删除账号后，`AccountAuditLog` 中的 `backfill` 记录仍在，审计与实体不一致，且没有批次 ID 可追溯"哪次回填被回滚"。
2. **门禁 9 未执行**：这是切换安全的核心演练（切换期新增数据在回滚时如何处理），完全空白。
3. **门禁 7 不完整**：只有 Chromium；旧业务页面未在隔离路由下验证，真实兼容缺口未被测量。
4. **门禁 10 的告警/保留缺失**：切换期若出现大量 `conflict`，当前没有任何告警通道。

## 4. 建议路径

要转为 **GO**，最小闭环：

1. 实现审计批次 ID + 追加回滚事件（门禁 5）；
2. 在 `smass_r22_g8_drill`（新建合成库）执行一次完整"切换 → 新增数据 → 回滚 → 校验"演练（门禁 9）；
3. 装 Firefox/WebKit 并跑同一套 8 例（门禁 7）；
4. 实现冲突计数与告警（至少日志级）+ 审计保留策略文档（门禁 10）；
5. 补测 10,000 规模与连接池（门禁 6 的可信度）。
